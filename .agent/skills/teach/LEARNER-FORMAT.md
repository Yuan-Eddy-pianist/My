# `.teach/LEARNER.md` format

`LEARNER.md` is the durable learner profile. It separates who the learner is from why they are studying this particular codebase.

Initialize it with the known personal context below, then update it only from explicit statements or demonstrated evidence.

## Template

```md
# Learner profile

## Existing strengths

- Master's-level electrical and computer engineering background
- Calculus, statistics, and linear algebra
- Digital signal and image processing
- Computer vision, machine learning, and deep learning
- Adversarial machine learning, including attacks and defenses
- Basic Python programming

## Building toward

1. Computer networks
2. Software engineering practice
3. Backend engineering
4. Databases
5. AI agents

## Long-term goal

Design, build, evaluate, deploy, and operate full-stack AI agents end to end.

## Teaching preferences

- Use accessible language without reducing technical depth.
- Define unfamiliar software terms on first use.
- Explain what and why before mechanics.
- Connect to signal flow, systems, probability, optimization, or computation graphs when the analogy genuinely clarifies the idea.
- Prefer real code paths, predictions, experiments, and feedback over passive exposition.
- Avoid condescension, pep talk, and mentor-role performance.

## Current edges

- {Concepts that are presently challenging or becoming important}

## Established capabilities

- {Capabilities supported by learning records or prior experience}
```

## Rules

- Do not treat the profile as a ceiling. Increase depth when the learner demonstrates readiness.
- Do not infer lack of ability from unfamiliarity with software terminology.
- Record preferences and stable background here; keep session-specific observations in `.teach/NOTES.md`.
- Cross-link significant claims about demonstrated capability to the relevant learning record.
